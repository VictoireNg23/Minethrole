# SIGSEGV dans le handler pendant exit : adaptation d8 proposée

GDB sur Grid5000 s'arrête dans `v8::internal::wasm::SignalHandler(int)+69`, instruction `mov (%rdi),%rax`, appelé par SIGALRM pendant `munmap/free/exit`. Cela confirme l'exécution du handler pendant la destruction du processus ; la donnée précise déjà invalide n'est pas identifiée par cette pile seule. Les adresses brutes des globals, le vecteur global et le FILE du patch ont des durées de vie à examiner. Les usages non async-signal-safe du handler restent un risque distinct non corrigé ici.

Le fichier `patches/chromium71/d8-stop-timer-before-teardown.patch` est une adaptation séparée, pas une modification des patches originaux. Il cible uniquement `src/d8.cc` de V8 7.1.302.31. Avant la collecte/destruction finale du contexte principal de d8, il ignore SIGALRM au niveau du processus puis désarme ITIMER_REAL, en vérifiant les erreurs système. L'ordre couvre les alarmes déjà pendantes. Il n'empêche aucun signal pendant les calculs du fixture, ne modifie aucun compteur, signature, profil, calcul ou seuil. Il supprime les échantillons pendant la destruction finale de d8, qui ne constituent pas une phase de calcul du module.

Portée : d8 Linux dans le scénario principal mono-instance testé. Ce correctif ne résout pas la durée de vie de toutes les instances, GC pendant un calcul, workers, modes de stress/multi-isolates ni l'arrêt des renderers Chromium. Il ne garantit pas qu'un handler déjà en cours sur un autre thread soit terminé. Chromium nécessitera une analyse de cycle de vie propre, et les originaux restent conservés comme référence scientifique.

Le contexte de `src/d8.cc` a été relu depuis le fichier de la révision exacte sur le miroir officiel V8 GitHub ; aucun arbre Chromium ni binaire n'a été téléchargé ou compilé dans Codex. L'ajout C++ suit la licence BSD du fichier V8 ciblé ; les mentions et licences originales du dépôt restent inchangées.

Le script d'application vérifie l'empreinte de l'adaptation, le HEAD historique, l'absence de changements sur d8.cc et le contexte Git avant modification, conserve une copie préalable et un diff dans un nouveau dossier. Il refuse une source déjà adaptée au lieu de l'écraser. Aucun rebuild n'est lancé automatiquement. Il faudra ensuite recompiler d8, répéter les neuf cas et le smoke test complet avant les douze signatures. Les succès de l'ancien binaire ne prouvent pas ceux du binaire corrigé.
