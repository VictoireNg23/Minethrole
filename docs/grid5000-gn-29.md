# Préparer GN historique séparément

Les hooks de `src/DEPS` reçus confirment `sysroot_x64`, `binutils`, `clang`, `gn_linux64`, ainsi que les actions de génération LASTCHANGE. Nous ne lançons pas les hooks globaux, notamment `landmines` et les actions de nettoyage.

Première préparation ciblée : `scripts/prepare-chromium71-gn.py WORKSPACE`. Il vérifie le HEAD Chromium attendu, lit `src/buildtools/linux64/gn.sha1`, télécharge l'objet correspondant du bucket officiel `chromium-gn` en HTTPS dans un nouveau répertoire temporaire et vérifie SHA-1 avant toute exécution. SHA-1 reproduit ici le mécanisme de sélection du hook historique ; ce n'est pas une signature cryptographique des auteurs. Une empreinte SHA-256 est aussi enregistrée pour la provenance de l'artefact reçu.

Le script ne remplace pas `src/buildtools/linux64/gn`, ne lance ni génération GN, ni hook, ni compilation. Il lance seulement le binaire vérifié avec `--version` dans son répertoire temporaire. Le téléchargement est limité à 64 Mio ; en cas d'erreur ou d'incompatibilité hôte, le rapport reste disponible. Le test local vérifie le refus d'une empreinte différente ; la disponibilité de l'objet et le démarrage du binaire nécessitent la sortie Grid5000.

Clang, binutils, sysroot et Node restent à préparer après validation de cette étape. Les binaires et sources Chromium ne sont pas ajoutés au dépôt GitHub.
